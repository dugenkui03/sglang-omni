# 8.1 qwen3-tts 数据流：预处理部分

范围：`Qwen3-TTS-12Hz-1.7B-Base`，使用上下文学习（In-Context Learning，ICL）的常规克隆模式，`preprocessing` 与 `tts_engine` 同进程。重点展开代码中已有中文注释的方法。

读图：节点第一行是**文件名**，第二行是**类名或模块名**；实线箭头写**方法名：处理职责**，虚线表示返回数据，开口箭头表示异步派发。同一箭头中的 `→` 表示连续调用，省略中间对象。

`wrapper` 是外部 `qwen_tts` 包的 `Qwen3TTSModel`；`model` 是本项目的 `Qwen3TTSTalker`，下图所用提示构建、说话人提取方法定义在其父类 `Qwen3TTSPromptBuilderMixin`。`Future` 来自 Python 标准库 `concurrent.futures`。

## ① 主链路：接收请求 → 音频特征 → 文本分词 → 交给引擎

启动时，[stages.py](../../sglang_omni/models/qwen3_tts/stages.py) 的 `create_preprocessing_executor()` 使用 `functools.partial()` 绑定预处理函数和默认参数，交给 `ThreadedSimpleScheduler`。下图从请求进入已启动的 Stage 开始。

<!-- mermaid:id=stage_preprocessing -->
```mermaid

    W-->>P: input_id [1, Ltext]：目标文本 Token IDs

    W-->>P: ref_id [1, Lref]：参考文本 Token IDs

    M-->>P: input_embeds、attention_mask、trailing_text_hidden、ref_code
    Note over P: prepare_qwen3_tts_request() 组装 Qwen3TTSPreparedRequest
    Note over P: preprocess_qwen3_tts_payload() 保存 prepared，并写入关联标记
    P-->>Q: StagePayload：state + prepared_marker
    Note over Q: run_one() 完成后，由 Future 回调触发 finish()
```

`_tokenize_texts()` 经 `processor` 将文本变成整数 Token IDs；`build_voice_clone_inputs()` 再构造向量（Embedding）输入。保存后的核心张量是 `prompt_input_embeds [P, 2048]`、`trailing_text_hidden [R, 2048]`、`ref_code [Tcode, 16]`。P 为提示长度，R 为后续文本长度；Ltext、Lref 包含文本模板标记。

同进程时，CPU 内存（CPU memory）中的 `_PREPARED_REQUESTS` 保存 prepared 对象及其 GPU 显存（GPU memory）张量引用，`prepared_marker` 用于关联。独立进程时改用 `store_prepared_qwen3_tts_payload()`；使用预处理 CUDA 流时记录 `ready_event`，供引擎消费前等待。

## ② 参考缓存：命中复用 → 正在编码则等待 → 首次编码

重点方法：[request_builders.py](../../sglang_omni/models/qwen3_tts/request_builders.py) 的 `prepare_qwen3_tts_base_request()`、[reference_encoder.py](../../sglang_omni/scheduling/reference_encoder.py) 的 `get_or_encode()` / `encode_leader()`。

```mermaid
    Note over P,R: 首次创建 ReferenceEncodeService，并绑定 Qwen3TTSAdhocReferenceHook
    P->>R: get_or_encode(state)：获取参考特征

        R->>H: store_artifact()：转为缓存格式，张量复制到 CPU 内存

        H-->>R: should_cache

            R->>C: put(cache_key, stored)：保存编码结果
        end
```

图中展开**有缓存键**的临时参考音频链路；`key is None` 时直接 `encode_leader()`，不查写缓存。上传并命名的音色优先查询 `speaker_cache`，未命中则调用同一 Hook 编码。省略错误、超时与中止分支。

缓存命中会跳过两条音频编码，目标文本仍按本次请求分词。`store_artifact()` 负责格式转换，`cache.put()` 才实际存入缓存；`inflight` 中的 Future 用于合并多个相同参考请求。

## ③ 双编码总览：提交声音编码 → 提取说话人向量 → 等待汇合

重点方法：[request_builders.py](../../sglang_omni/models/qwen3_tts/request_builders.py) 的 `Qwen3TTSAdhocReferenceHook.encode_one()`。先 `submit()`，随后在当前工作线程提取说话人向量，最后通过 `ref_code_future.result()` 收集声音编码。

<!-- mermaid:id=parallel_encoders -->
```mermaid
%%{init: {"theme": "neutral"}}%%
sequenceDiagram
    participant H as request_builders.py<br/>Qwen3TTSAdhocReferenceHook
    participant W as qwen3_tts_model.py<br/>Qwen3TTSModel
    participant B as request_builders.py<br/>Qwen3TTSRefCodeBatcher
    participant F as _base.py<br/>Future（ref_code_future）
    participant M as sglang_model.py<br/>Qwen3TTSPromptBuilderMixin
    H->>W: _normalize_audio_inputs()：统一参考音频输入
    opt 输入为路径、URL 或 Base64 字符串
        W->>W: _load_audio_to_np()：解码音频、转单声道
        Note over W: 内部调用 librosa.load() 或 sf.read()
    end
    W-->>H: waveform [N]、sample_rate：CPU 内存
    H->>B: submit(waveform, sample_rate)：将声音编码任务入队
    B-->>H: 立即返回 ref_code_future
    par 声音编码：专用后台线程 qwen3-tts-ref-code
        B->>B: run() → drain()：从队列取任务
        B->>B: encode_waveform()：逐条生成参考音频整数编码，见图④
        B->>B: synchronize_outcomes()：等待声音编码 GPU 计算完成
        B->>F: set_result(ref_code)：使声音编码结果可读取
    and 说话人编码：当前预处理工作线程
        Note over H: 按需 librosa.resample()，对齐说话人编码器采样率
        H->>M: extract_speaker_embedding()：提取说话人特征，见图⑤
        M-->>H: speaker_embedding [2048]：浮点向量
    end
    H->>F: result(timeout=130)：等待并读取声音编码
    F-->>H: ref_code [Tcode, 16]：整数码本编号
    Note over H: encode_one() 组装 VoicePrompt，并返回 VoicePrompt、ref_text
```

`par` 表示两条工作链可重叠，不保证同时完成。声音编码使用专用 CUDA 流；说话人编码使用当前预处理工作线程的 CUDA 流。`x_vector_only_mode=True` 时跳过声音编码，仅提取说话人向量。

这里的 `ref_code_future` 等待**单个请求中的声音编码**，与图②合并相同参考请求的 `inflight` Future 不同。两项输出都是参考特征，后续由 `tts_engine` 生成目标语音的音频编码。

## ④ 声音编码：波形 → 整数码本编号

重点方法：[request_builders.py](../../sglang_omni/models/qwen3_tts/request_builders.py) 的 `Qwen3TTSRefCodeBatcher.encode_waveform()`；CUDA 图封装在 [reference_encoder_cuda_graph.py](../../sglang_omni/models/qwen3_tts/reference_encoder_cuda_graph.py)。

<!-- mermaid:id=codec_encoding -->
```mermaid
%%{init: {"theme": "neutral"}}%%
sequenceDiagram
    participant B as request_builders.py<br/>Qwen3TTSRefCodeBatcher
    participant T as qwen3_tts_tokenizer.py<br/>Qwen3TTSTokenizer
    participant G as reference_encoder_cuda_graph.py<br/>Qwen3TTSReferenceEncoderCudaGraphRunner
    participant E as modeling_qwen3_tts_tokenizer_v2.py<br/>Qwen3TTSTokenizerV2Encoder
    B->>T: _normalize_audio_inputs()：转单声道、对齐采样率
    T-->>B: audio[0] [Ncodec]：CPU 内存中的 float32 波形
    B->>B: encode_waveform() 内 torch.from_numpy()：转为 CPU 张量
    opt 已启用参考编码 CUDA 图
        B->>G: encode(samples)：按帧数选择已捕获的图
        alt 有匹配桶
            G->>G: encode() 内 copy_() / zero_()：拷入 GPU 显存、补齐
            G->>G: encode() 内 graph.replay()：重放声音编码计算
            G-->>B: ref_code [Tcode, 16]；encode_waveform() 直接返回
        else 超过最大桶
            G-->>B: None；继续普通执行路径
        end
    end
    opt 未启用 CUDA 图，或图编码返回 None
        B->>B: encode_waveform()：计算 Tcode，分配并补齐 GPU 输入
        Note over B: values [1, 1, Tcode × hop]：批次、声道、采样点
        B->>E: encode(values, num_quantizers=16)：波形转整数编码
        E-->>B: audio_codes [1, 16, Tcode]
        B->>B: encode_waveform() 内切片、transpose(0, 1)：转为帧在前
        Note over B: 返回 ref_code [Tcode, 16]
    end
```

`Tcode = ceil(Ncodec / hop)`；每帧有 16 个码本（Codebook）编号。返回的是整数编号，后续才查表转成向量。`Qwen3TTSTokenizerV2Encoder.encode()` 继承自 `transformers` 的 `MimiModel`；当前链路直接调用该编码器，没有经过 `Qwen3TTSTokenizer.encode()` 包装方法。

## ⑤ 说话人编码：波形 → 对数梅尔频谱 → 音色向量

重点方法：[sglang_model.py](../../sglang_omni/models/qwen3_tts/sglang_model.py) 的 `extract_speaker_embedding()`、[speaker_encoder_cuda_graph.py](../../sglang_omni/models/qwen3_tts/speaker_encoder_cuda_graph.py) 的 `embed()` / `mel()`。

<!-- mermaid:id=speaker_encoding -->
```mermaid
%%{init: {"theme": "neutral"}}%%
sequenceDiagram
    participant H as request_builders.py<br/>Qwen3TTSAdhocReferenceHook
    participant M as sglang_model.py<br/>Qwen3TTSPromptBuilderMixin
    participant S as speaker_encoder_cuda_graph.py<br/>Qwen3TTSSpeakerEncoderCudaGraphRunner
    participant E as modeling_qwen3_tts.py<br/>Qwen3TTSSpeakerEncoder
    H->>M: extract_speaker_embedding(audio, sr)：校验采样率、提取向量
    M->>S: embed(waveform)：执行频谱转换与说话人编码
    S->>S: mel(waveform_tensor)：CPU 波形转对数梅尔频谱
    Note over S: [1, Nspeaker] → [1, 128, Tmel]；均在 CPU 内存
    Note over S: mel() 内部：反射补齐 → STFT → 幅度谱 → 梅尔滤波 → log
    S->>S: embed() 内 to(device, dtype)：频谱搬到 GPU 显存
    alt 无匹配的 CUDA 图桶
        S->>E: forward(mels.transpose(1, 2))：提取说话人向量
        Note over E: 输入 [1, Tmel, 128]；特征提取 → 聚合 → 池化 → 投影
        E-->>S: [1, 2048]；embed() 取第 0 项得到 [2048]
    else 有匹配的 CUDA 图桶
        S->>S: embed() 内 copy_() / fill_()：填充静态频谱与有效帧数
        S->>S: embed() 内 graph.replay()：重放已捕获的说话人计算
        Note over S: 捕获时执行 encode_bucketed()，复用同一说话人编码器权重
        S->>S: embed() 内 clone()：取得本次结果 [2048]
    end
    S-->>M: speaker_embedding [2048]
    M-->>H: speaker_embedding
```

`Tmel` 是梅尔频谱（Mel Spectrogram）帧数，`Tcode` 是音频编码帧数，两者不同。`mel()` 的 128 维表示每帧的频带特征，最终 `[2048]` 向量表示整段参考音频的说话人特征。

日志可沿 `参考音频解码完成` → `声音波形规范化` / `对数梅尔频谱计算完成` → `说话人特征向量提取完成` → `参考编码完成` 定位；双编码日志可能交错。CUDA 图重放不会重新执行被捕获区域中的 Python 日志。
